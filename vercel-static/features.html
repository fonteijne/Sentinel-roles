2026-07-13df32fc9

Add a Prometheus /metrics endpoint for observability

/health is a point-in-time snapshot: it can't tell you the dispatch rate, how often the pipeline escalates to humans, or whether sweeps have been quietly failing over the last hour. For a system meant to run unattended, that trend visibility is what makes it monitorable and alertable — and it was missing.

2026-07-1325eda8b

Harden control-plane auth: constant-time check, header support

The four mutating endpoints (/webhook/jira, /sweep, /pause, /resume) can freeze or nudge the whole pipeline, but each authenticated with a duplicated `token != WEBHOOK_SECRET` check. Three problems: the comparison is not constant-time (a timing side-channel that leaks the secret byte by byte); the secret was only accepted as a URL query param, so it lands in access logs, proxies and browser history; and the logic was copy-pasted four times. Adding /pause and /resume earlier widened the blast radius — the same shared token now freezes the entire pipeline.

2026-07-1308c5629

Rotate the audit log so it can't fill the data volume

The audit trail (audit.jsonl) is append-only and written from the orchestrator's and agents' hot paths — dispatch, escalation, transitions, reclaims (21 call sites). It lives on the same fixed /data volume as the agent workspaces and the pause-state file, with no rotation. In a continuously-running deployment it grows without bound until the volume fills, at which point record() raises OSError inside those hot paths (a crashed sweep, a crashed agent run, cascading retries). For a platform whose whole traceability story is this file, that is a real operational failure mode.

2026-07-139d7d340

Retry transient Jira failures with backoff instead of failing hard

Jira is the platform's single source of truth and its most-called dependency — dozens of calls per agent run — yet the client had no retry at all, while the LLM client already retried 3x. Jira Server/DC routinely returns 429 (rate limiting) and 502/503/504 (GC pauses, reindexing, reverse-proxy failover). Every such blip either wasted agent turns, skewed lease timing, or counted toward the orchestrator's "degraded" health threshold — two transient blips during sweeps would flag the whole platform degraded while Jira was actually fine.

2026-07-135d707c3

Verify workflow edge exists before posting handoff payloads

transition_with_handoff posted the handoff comment and only then discovered whether the Jira workflow allows the transition. A missing workflow edge (statuses exist but the transition between them was never configured — a misconfiguration doctor cannot detect, since it checks statuses, not edges) left an orphaned agent_handoff comment on an unmoved ticket, once per retry. The transition pre-flight now checks the target is reachable via the workflow's available transitions before anything is written, and the error names the available targets so the agent can escalate the misconfiguration precisely.

2026-07-136ec27f2

Surface sweep failures as 'degraded' health, pin dependency majors

An expired PAT or unreachable Jira made sweeps fail forever while /health kept reporting ok — invisible to monitoring. The orchestrator now tracks consecutive sweep failures and the last error; /health flips to 'degraded' after two consecutive failures and exposes both fields.

2026-07-13b90b5ea

Make rework counting idempotent across router retries

increment_rework bumped the counter on every call: if a Rework Router run crashed or hit the turn cap after incrementing but before transitioning, the orchestrator's retry counted the same rejection again — phantom bounces that trip the loop-breaker (rework_count > 2) early and freeze tickets that only actually bounced once. The rework state now records the comment id of the counted rejection payload and skips re-counting it, reporting already_counted to the agent instead.

2026-07-1250921a6

Heartbeat queue-claimed leases, test the queue-role flow end to end

The heartbeat task only ran for ticket-scoped roles, so tickets claimed mid-run by queue roles (Planner, Deployment, Release) via claim_ticket never got heartbeats — a deploy or release batch running past the 30-minute lease timeout would have its leases reclaimed by the sweep while still working. The heartbeat loop now refreshes every lease the run holds, and drops a ticket from the run's holdings if its lease was taken over (humans win).
